# ScoreMosaic Web Preview v1

Status: **public fixture-only GitHub Pages preview deployed and verified; E7-H local score-renderer build path ready**

Contract: `contracts/web-preview-v1.json`

Current architecture state: `contracts/architecture-current-state-v1.json`

Web Preview v1 packages the existing Stage 10 product experience, Stage 11 typed local application scripts, the exact ST Score Editor Core browser artifact, and OSMD `2.1.1` into one deterministic static artifact. The user has explicitly authorized publishing this fixture-only artifact through GitHub Pages. That authority is narrow: it does not activate browser API networking, authentication, persistence, real upload, production data, server writes, approval, publication, or production traffic.

This workstream is unnumbered and does not create Stage 12.

## Purpose

The preview exists so the current ScoreMosaic interface can be inspected as a real browser experience without pretending that the product is connected to production.

```text
Stage 10 UI source
        +
Stage 11 local typed application scripts
        +
exact ST Score Editor Core browser bundle
        +
local OSMD 2.1.1 distribution + BSD license
        ↓
scripts/build_web_preview.py
        ↓
verified standalone static artifact
        ↓
CI security validation
        ↓
GitHub Pages artifact
        ↓
PUBLIC FIXTURE-ONLY PREVIEW
```

## Source-of-truth behavior

The build does not create a second product implementation. It copies the checked-in Stage 10 UI assets and Stage 11 application scripts, verifies the exact local renderer/build inputs, and composes them in the generated artifact.

The source Stage 10 score mock is deliberately retained as the renderer-independent fallback. The generated artifact adds a real score-render host beside it. The fallback is hidden only after the exact local OSMD host successfully renders MusicXML generated by the local ST Score Editor Core session.

A visible banner is injected into the generated page:

```text
NON-PRODUCTION PREVIEW · FIXTURE DATA ONLY · LOCAL RENDERER · NO API · NO PERSISTENCE
```

The generated directory is not committed to the repository. Re-running the builder against the same source tree and the same exact build inputs must produce byte-identical files.

## Exact local build inputs

The preview builder requires explicit local files and does not download dependencies itself:

- ST Score Editor Core commit `b317abef915d1e16b37572221a38feb3e504450d` browser bundle;
- its `ST_SCORE_EDITOR_CORE_BROWSER_BUNDLE` manifest;
- `opensheetmusicdisplay@2.1.1` package main bundle;
- the exact OSMD package metadata;
- the OSMD BSD-3-Clause license text.

The core manifest byte length and SHA-256 are revalidated before copying. OSMD package name, version, license and package-main relationship are also revalidated. The generated artifact contains no CDN or other remote runtime reference.

## Security boundary

The preview retains the Stage 10 CSP boundary:

```text
default-src 'none'
style-src 'self'
img-src 'self' data:
connect-src 'none'
script-src 'self'
object-src 'none'
frame-src 'none'
base-uri 'none'
form-action 'none'
```

First-party ScoreMosaic browser code and the ST Score Editor Core bundle are checked for forbidden network/persistence capabilities. OSMD is a third-party renderer whose distribution can contain URL-loading implementation paths; therefore the security claim is intentionally different for that library: ScoreMosaic passes only an in-memory MusicXML string to the OSMD host, never a URL, and the page CSP keeps all connection attempts blocked with `connect-src 'none'`.

The renderer remains presentation-only. SVG coordinates, DOM ids, glyph objects and renderer internals never become edit authority.

The fixture remains non-authoritative. Structured Edit may create an immutable **local core revision** for fixture inspection, but it cannot create or persist a ScoreMosaic server `ScoreEditCommand` or `TeacherScoreRevision`, and it cannot approve, publish, or activate production state.

## CI artifact

`.github/workflows/web-preview-v1-ci.yml` remains the non-deploying verification workflow. It checks out the exact core commit, runs core CI, installs the exact OSMD package into the runner's temporary build area, validates the static preview, and uploads a downloadable Actions artifact with `contents: read` only.

Uploading that CI artifact is not itself a public deployment.

## GitHub Pages deployment workflow

`.github/workflows/web-preview-pages-deploy.yml` is the only authorized public preview deployment path. It is intentionally constrained:

- deployment source is `main` only;
- pull requests never execute the Pages deployment;
- the build job has only `contents: read`;
- the deploy job has only `pages: write` and `id-token: write`;
- all external GitHub Actions are pinned to full immutable commit SHAs;
- no production secret or provider credential is supplied;
- no `configure-pages` auto-enablement token is used;
- the same exact core/OSMD artifact checks and preview regressions run before upload;
- deployment targets the `github-pages` environment only.

The repository-level GitHub Pages setting is not inferred from repository code. Initial operational evidence is successful deployment run [32652403651](https://github.com/khfy7wpr5p-maker/scoremosaic-platform/actions/runs/32652403651) at commit `33555ed152d1f8f3bdec0072bec7693c29b2aa1c`, together with the reachable public site at [khfy7wpr5p-maker.github.io/scoremosaic-platform](https://khfy7wpr5p-maker.github.io/scoremosaic-platform/). Later `main` deployments may supersede that revision without invalidating the recorded enablement/reachability evidence.
